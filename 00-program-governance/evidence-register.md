# Evidence Register

Track objective proof for every meaningful learning and architecture claim.

## Evidence logging rules

1. Every phase completion claim must have linked evidence.
2. Evidence IDs must be unique and stable (e.g., `EV-03-ARCH-001`).
3. Evidence should be immutable or versioned (commit hash, tagged artifact, report snapshot).
4. If evidence is superseded, mark prior item as superseded rather than deleting it.

## Artifact type reference

| Code | Meaning |
|---|---|
| NOTE | Study notes |
| LAB | Lab implementation/runs |
| ARCH | Architecture diagrams/views |
| ADR | Architecture decision record |
| EVAL | Evaluation report/results |
| SEC | Security controls/threat model |
| RUN | Runbook or operational procedure |
| COST | Cost model/analysis |
| GOV | Governance checklist/sign-off |

## Evidence quality rubric

| Rating | Criteria |
|---|---|
| A | Reproducible, reviewable, traceable to commit and requirement |
| B | Reviewable and traceable, minor reproducibility gaps |
| C | Partial proof; missing either traceability or review depth |
| D | Weak proof; cannot support completion claims |
